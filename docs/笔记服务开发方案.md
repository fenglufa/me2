# 笔记服务开发方案

## 一、产品定位

**AI 笔记系统是整个 App 的用户侧"生活输入引擎"。**

用户的所有生活记录（文字、情绪、想法、任务、记账等）通过 AI 自动分析、分类、结构化，并反馈到分身系统，形成闭环：

```
用户笔记 → AI 结构化 → 分身理解 → 分身行为/日记 → 用户再记录
```

**核心价值**：
- 笔记是"用户自己的内容"，是产品唯一不会被替代的资产
- "分身"是陪伴，"笔记"才是沉淀
- 笔记是输入接口，分身日记是输出接口

## 二、技术架构

### 2.1 服务架构

```
Note Service (RPC)
├── 笔记 CRUD
├── AI 分类（调用 AI Service）
├── 结构化数据存储
├── TODO 管理
├── 记账管理
└── 事件触发（调用 Diary Service）

依赖服务：
- AI Service: 笔记分类、情绪分析、摘要生成
- Diary Service: 接收笔记事件，生成分身日记
- Avatar Service: 获取分身信息
```

### 2.2 数据库设计（MySQL）

#### 笔记主表 (notes)
```sql
CREATE TABLE `notes` (
  `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `avatar_id` BIGINT DEFAULT NULL COMMENT '关联的分身ID（可选）',
  `raw_text` TEXT NOT NULL COMMENT '原始笔记内容',
  `ai_summary` VARCHAR(500) DEFAULT '' COMMENT 'AI生成的摘要',
  `types` JSON DEFAULT NULL COMMENT '笔记类型数组 ["emotion","todo","expense"]',
  `emotion_data` JSON DEFAULT NULL COMMENT '情绪数据 {type:"sad",score:0.8}',
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  `updated_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_user_id` (`user_id`),
  INDEX `idx_avatar_id` (`avatar_id`),
  INDEX `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='笔记主表';
```

#### TODO 表 (note_todos)
```sql
CREATE TABLE `note_todos` (
  `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
  `note_id` BIGINT NOT NULL COMMENT '关联笔记ID',
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `title` VARCHAR(500) NOT NULL COMMENT 'TODO标题',
  `due_date` DATE DEFAULT NULL COMMENT '截止日期',
  `status` TINYINT DEFAULT 0 COMMENT '状态 0:未完成 1:已完成',
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  `completed_at` TIMESTAMP NULL DEFAULT NULL,
  INDEX `idx_note_id` (`note_id`),
  INDEX `idx_user_id` (`user_id`),
  INDEX `idx_status` (`status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='TODO表';
```

#### 记账表 (note_expenses)
```sql
CREATE TABLE `note_expenses` (
  `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
  `note_id` BIGINT NOT NULL COMMENT '关联笔记ID',
  `user_id` BIGINT NOT NULL COMMENT '用户ID',
  `item` VARCHAR(200) NOT NULL COMMENT '消费项目',
  `amount` DECIMAL(10,2) NOT NULL COMMENT '金额',
  `category` VARCHAR(50) DEFAULT 'other' COMMENT '分类 food/transport/shopping/other',
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX `idx_note_id` (`note_id`),
  INDEX `idx_user_id` (`user_id`),
  INDEX `idx_category` (`category`),
  INDEX `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='记账表';
```

### 2.3 AI 分类逻辑

用户提交笔记后，AI 自动识别类型：

| 类型 | 示例 | 说明 |
|------|------|------|
| emotion | "今天好累" | 情绪笔记 |
| event | "我今天和老板吵架了" | 事件记录 |
| idea | "我有个新计划" | 想法灵感 |
| todo | "记得明天买牛奶" | 待办事项 |
| goal | "2025 我要换工作" | 目标 |
| expense | "午饭 35 元" | 记账 |

**注意**：一条笔记可以同时包含多个类型。

## 三、核心功能流程

### 3.1 用户写笔记流程

```
1. 用户输入："今天心情很混乱"
2. 用户点击保存
3. Note Service 接收请求
4. 调用 AI Service 进行分类和情绪分析
   - 类型：emotion
   - 情绪：sad (0.82)
5. 存储结构化数据到 MySQL
6. 触发事件：调用 Diary Service
   - 传递：用户情绪低落事件
7. Diary Service 生成分身日记：
   "今天我感受到你有些不安，我也跟着安静了下来。"
8. 返回成功
```

### 3.2 记账流程

```
输入："午饭 35 咖啡 20"

AI 识别：
- 两条账单
- 自动归类：food/drink
- 自动统计每日消费

存储到 note_expenses 表
```

### 3.3 TODO 流程

```
输入："明天买牛奶"

AI 识别：
- 类型：todo
- 提取任务：买牛奶
- 截止日期：明天

存储到 note_todos 表
分身可能会提醒："记得明天要买牛奶哦"
```

## 四、API 接口设计

### 4.1 RPC 接口（Note Service）

```protobuf
service NoteService {
  // 创建笔记
  rpc CreateNote(CreateNoteRequest) returns (CreateNoteResponse);

  // 获取笔记列表
  rpc GetNotes(GetNotesRequest) returns (GetNotesResponse);

  // 获取笔记详情
  rpc GetNoteDetail(GetNoteDetailRequest) returns (GetNoteDetailResponse);

  // 更新笔记
  rpc UpdateNote(UpdateNoteRequest) returns (UpdateNoteResponse);

  // 删除笔记
  rpc DeleteNote(DeleteNoteRequest) returns (DeleteNoteResponse);

  // 获取 TODO 列表
  rpc GetTodos(GetTodosRequest) returns (GetTodosResponse);

  // 更新 TODO 状态
  rpc UpdateTodoStatus(UpdateTodoStatusRequest) returns (UpdateTodoStatusResponse);

  // 获取记账列表
  rpc GetExpenses(GetExpensesRequest) returns (GetExpensesResponse);

  // 获取记账统计
  rpc GetExpenseStats(GetExpenseStatsRequest) returns (GetExpenseStatsResponse);
}
```

### 4.2 Gateway API 接口

```
POST   /api/notes              创建笔记
GET    /api/notes              获取笔记列表
GET    /api/notes/:id          获取笔记详情
PUT    /api/notes/:id          更新笔记
DELETE /api/notes/:id          删除笔记

GET    /api/notes/todos        获取 TODO 列表
PUT    /api/notes/todos/:id    更新 TODO 状态

GET    /api/notes/expenses     获取记账列表
GET    /api/notes/expenses/stats  获取记账统计
```

## 八、关键技术点

### 8.1 AI 分类准确性

- 使用 DeepSeek 进行分类
- 设计清晰的 Prompt 模板
- 支持多标签分类（一条笔记可以有多个类型）

### 8.2 性能优化

- 笔记列表分页查询
- 使用索引优化查询性能
- AI 分类异步处理（可选）

### 8.3 数据一致性

- 笔记删除时级联删除 TODO 和记账记录
- 使用事务保证数据一致性

### 8.4 扩展性

- JSON 字段存储 AI 分析结果，便于扩展
- 预留 avatar_id 字段，支持多分身场景

## 九、开发规范

- 代码文件使用下划线命名（snake_case）
- 单个文件不超过 500 行
- 使用 `--style go_zero` 生成代码
- 所有 RPC 方法都需要验证用户权限
- 数据库操作封装在 Model 层

## 十二、风险与挑战

### 12.1 技术风险

- AI 分类准确性不足
- 性能问题（大量笔记查询）
- 数据隐私和安全

### 12.2 产品风险

- 用户不习惯写笔记
- 分身联动体验不够自然
- 功能过于复杂

### 12.3 应对措施

- 持续优化 AI Prompt
- 数据库索引优化
- 简化用户操作流程
- 提供快捷入口和模板
