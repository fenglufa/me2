# 对话服务设计方案

## 1. 架构概览

```
Flutter App (WebSocket)
    ↓
Gateway (WebSocket Handler + JWT认证)
    ↓
Dialogue Service (RPC 流式)
    ↓
AI Service (RPC)
    ↓
DeepSeek API
```

## 2. 服务职责划分

### 2.1 Gateway 层
- JWT 认证,提取 user_id 和 avatar_id
- WebSocket 连接管理和升级
- 将 WebSocket 消息转发到 Dialogue RPC
- 将 RPC 流式响应推送到 WebSocket 客户端

### 2.2 Dialogue Service
- 会话管理(存储对话历史到数据库)
- 上下文构建:
  - 分身人格信息(从 Avatar Service 获取)
  - 最近事件(从 Event Service 获取)
  - 当前会话的对话历史(从数据库获取最近 N 条)
  - 长期记忆(可选,后续通过 Memory Service 实现 RAG 检索)
- 调用 AI Service 的 Chat/ChatStream RPC
- 返回流式响应

### 2.3 AI Service
- Prompt 模板管理
- 调用 DeepSeek API
- Token 使用统计和成本计算
- 调用日志记录

## 3. 数据库设计

### 3.1 对话会话表 (dialogue_sessions)
```sql
CREATE TABLE dialogue_sessions (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    avatar_id BIGINT NOT NULL,
    title VARCHAR(200),
    created_at BIGINT NOT NULL,
    updated_at BIGINT NOT NULL,
    INDEX idx_user_avatar (user_id, avatar_id)
);
```

### 3.2 对话消息表 (dialogue_messages)
```sql
CREATE TABLE dialogue_messages (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    session_id BIGINT NOT NULL,
    role VARCHAR(20) NOT NULL,  -- user/assistant
    content TEXT NOT NULL,
    created_at BIGINT NOT NULL,
    INDEX idx_session (session_id)
);
```

## 4. API 设计

### 4.1 Gateway REST API
```
GET  /api/v1/dialogue/sessions          # 获取会话列表
POST /api/v1/dialogue/sessions          # 创建新会话
GET  /api/v1/dialogue/sessions/:id      # 获取会话详情
GET  /api/v1/dialogue/messages/:session_id  # 获取对话历史
```

### 4.2 Gateway WebSocket API
```
WS /api/v1/dialogue/stream?session_id=xxx

# 客户端发送消息格式
{
    "session_id": 123,
    "message": "你好"
}

# 服务端推送消息格式(流式)
{
    "content": "你",
    "done": false
}
{
    "content": "好",
    "done": false
}
{
    "content": "!",
    "done": true,
    "message_id": 456
}
```

### 4.3 Dialogue RPC 接口
```protobuf
service Dialogue {
  // 创建会话
  rpc CreateSession(CreateSessionRequest) returns (CreateSessionResponse);

  // 获取会话列表
  rpc GetSessions(GetSessionsRequest) returns (GetSessionsResponse);

  // 获取对话历史
  rpc GetMessages(GetMessagesRequest) returns (GetMessagesResponse);

  // 流式对话
  rpc ChatStream(ChatStreamRequest) returns (stream ChatStreamResponse);
}

message ChatStreamRequest {
  int64 session_id = 1;
  string message = 2;
  int64 user_id = 3;
  int64 avatar_id = 4;
}

message ChatStreamResponse {
  string content = 1;
  bool done = 2;
  int64 message_id = 3;  // 最后一条消息返回
}
```

## 5. 实现步骤

### 5.1 创建 Dialogue Service
```bash
cd backend/services
goctl rpc new dialogue
```

### 5.2 定义 Proto 文件
编写 `dialogue.proto`,定义上述 RPC 接口

### 5.3 生成代码
```bash
cd dialogue/rpc
goctl rpc protoc dialogue.proto --go_out=. --go-grpc_out=. --zrpc_out=.
```

### 5.4 实现核心逻辑
- `chat_stream_logic.go`: 实现流式对话逻辑
  - 获取分身人格
  - 获取最近事件
  - 构建上下文
  - 调用 AI Service
  - 保存对话记录

### 5.5 Gateway 集成
- 在 `gateway/api/internal/handler` 添加 WebSocket handler
- 手动注册 WebSocket 路由
- 实现 WebSocket ↔ RPC Stream 转发

### 5.6 前端集成
- 使用 `web_socket_channel` 包
- 连接 `ws://domain/api/v1/dialogue/stream`
- 发送消息并接收流式响应

## 7. go-zero WebSocket 实现要点

### 7.1 自定义 Handler
go-zero 不原生支持 WebSocket 路由定义,需要手动实现:

```go
// gateway/api/internal/handler/dialogue/stream_handler.go
func StreamHandler(svcCtx *svc.ServiceContext) http.HandlerFunc {
    upgrader := websocket.Upgrader{
        CheckOrigin: func(r *http.Request) bool { return true },
    }

    return func(w http.ResponseWriter, r *http.Request) {
        // 1. JWT 认证(从 query 或 header 获取 token)
        token := r.URL.Query().Get("token")
        userID, avatarID := parseToken(token)

        // 2. 升级 WebSocket
        conn, _ := upgrader.Upgrade(w, r, nil)
        defer conn.Close()

        // 3. 接收客户端消息
        for {
            var msg struct {
                SessionID int64  `json:"session_id"`
                Message   string `json:"message"`
            }
            conn.ReadJSON(&msg)

            // 4. 调用 Dialogue RPC 流式接口
            stream, _ := svcCtx.DialogueRpc.ChatStream(ctx, &dialogue.ChatStreamRequest{
                SessionId: msg.SessionID,
                Message:   msg.Message,
                UserId:    userID,
                AvatarId:  avatarID,
            })

            // 5. 转发流式响应
            for {
                resp, err := stream.Recv()
                if err != nil {
                    break
                }
                conn.WriteJSON(resp)
            }
        }
    }
}
```

### 7.2 手动注册路由
```go
// gateway/api/gateway.go
func main() {
    server := rest.MustNewServer(c.RestConf)
    ctx := svc.NewServiceContext(c)

    // 标准 REST 路由
    handler.RegisterHandlers(server, ctx)

    // 手动注册 WebSocket 路由
    server.AddRoute(rest.Route{
        Method:  http.MethodGet,
        Path:    "/api/v1/dialogue/stream",
        Handler: dialogue.StreamHandler(ctx),
    })

    server.Start()
}
```

## 8. 性能优化

### 8.1 连接池
- Gateway 到 Dialogue Service 使用 gRPC 连接池
- Dialogue Service 到 AI Service 使用连接池

### 8.2 缓存
- 分身人格信息缓存(Redis, TTL 1小时)
- 最近事件缓存(Redis, TTL 5分钟)

### 8.3 限流
- 每个用户每分钟最多 20 条消息
- 使用 Redis 实现滑动窗口限流

## 9. 监控指标

- WebSocket 连接数
- 消息发送/接收速率
- RPC 调用延迟
- AI Service token 使用量
- 错误率

## 10. 分阶段实现

### 10.1 MVP 阶段 (当前实现)
**必需服务**: Gateway + Dialogue Service + AI Service + Avatar Service + Event Service

**功能范围**:
- 基础对话功能
- 上下文构建:
  - 分身人格信息
  - 最近 3-5 条事件
  - 当前会话对话历史
- 流式响应
- 会话管理

**不包含**: Memory Service (长期记忆系统)

### 10.2 后续迭代
**新增服务**: Memory Service

**功能扩展**:
- 长期记忆系统:
  - 向量数据库(Milvus/Qdrant)
  - RAG 检索相关记忆
  - 记忆重要性评分
  - 记忆遗忘机制
- 情绪识别和响应
- 对话主题分类
- 用户反馈机制(点赞/点踩)
- 多分身对话切换
